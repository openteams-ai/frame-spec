# Engineering Documentation Style

## Goals

- Make technical guidance easy to scan and act on.
- Preserve accuracy while staying readable for mixed audiences.

## Terminology

- Prefer concrete tool or interface names over vague references.
- Define internal abbreviations before using them repeatedly.

## Style

- Lead with the task outcome before implementation detail.
- Use examples when a concept would otherwise stay abstract.
- Call out assumptions, constraints, and known tradeoffs explicitly.
